# 形式化审计台

## 对巨型 Lean 形式化声明的独立复核：能力、方法、边界

编制：2026-11-23　|　第一个标的：Alpöge–Claude 黎曼猜想形式化库（175,187 文件 / 17,374,215 行）
　|　第二轮：同一套方法反过来审我们自己的 QRH 库（见 §3.1）

---

## 0. 一页结论

**问题**：当一个数学结论以「1,700 万行代码 + 全库零 sorry」的形式发布时，外部没有任何既有手段判断它是否真的证了它宣称的东西。同行评审看不懂代码，代码审计员不懂数学，媒体只能转述作者的话。

**我们做了什么**：把这套手段做出来，并在一份真实的 1,700 万行库上完整跑通一遍。交付四件套：数字指纹、体量与结构统计、文本层全树扫描、语句层公理抽取与「同物」核验。

**三个硬数字**：

- 分卷 join 后的 SHA-256 = `9631b4f0…f49c7fc`，与论文正文所载**逐字节一致**——先证明我们查的就是那一份物体；
- 175,187 个 `.lean` 文件、17,374,215 行、1,066,087 条声明；
- 全树文本层：`axiom` / `constant` / `opaque` / `unsafe` / `sorry` / `admit` / `native_decide` **全部为 0**。

**一条机检结论**：对 4 个核心 `def`（含 `RiemannHypothesis`、`RiemannZetaZerosOnLine`）抽取公理集，结果全部只有三条 Lean 基础公理 `propext`、`Classical.choice`、`Quot.sound`；且这两个陈述经 `rfl` 判定相等——**「他们证的是不是他们宣布的那个命题」被机器确认，不靠信任。**

**一条边界，必须先说死**：我们不给数学正确性背书，只给「没有藏东西」背书。这篇论文自己承认主不等式 (M) 未证，那是数学缺口，不是审计能补的。

## 1. 问题的形状：三种「洗白」通道

形式化声明可以造假的地方只有三处。我们的产品线就是逐条堵这三处。

| 通道 | 手法 | 传统手段为何失效 | 我们的手段 | 覆盖度 |
|---|---|---|---|---|
| 一、文本层留洞 | `sorry` / `admit` / `axiom` / `opaque` / `unsafe` / `native_decide` | 没人真的逐文件读 17M 行 | 全树正则全扫，逐关键字计数 | **完全覆盖** |
| 二、语句层偷弱 | 形式语句写得比论文命题弱（偷换量词、去掉一致性、换掉定义域） | 读代码的人看不出「这不是原文那句」 | 逐字/行号/公式级「同物」核验 | **完全覆盖**（需论文可比对） |
| 三、kernel 层藏货 | `olean` 里带进构造子或公理，源码干净 | 需要全量 `#print axioms`，通常跑不动 | 语句层公理抽取 + 判等切片 | **部分覆盖**（本机不可达时） |

## 3. 方法论产出：statement-first 审计范式

全量 `#print axioms` 主定理在这台工作站上**不可达**：依赖闭包 175,133/175,187 个模块，峰值内存 6.4–7.8 GB/进程，而本机提交上限只有 39.7 GB。这不是调参问题，是物理上限。

我们给的替代范式是：

1. 只编译 **`Statements`** 模块（它只依赖 Mathlib，不依赖那 17 万文件）；
2. 对其中 4 个核心 `def` 逐个取 `#print axioms`；
3. 对相互等价的陈述做判等（`rfl` / 定义展开）；
4. 产出物只有 20,784 字节的 `Statements.olean`。

**这套范式的价值不在这一次，而在它可复制**：任何一个巨型形式化项目，只要把「陈述层」和「证明层」分离，外部审计就能在一台普通工作站上完成。这是我们真正的产品能力——**把「不可审计」降级为「可审计的关键切片」。**

## 3.1 自审：同一套方法用在自己的库上

方法不能只对着别人。「有没有藏东西」这条判据，我们对自己的 `QRH` 库也执行了一遍（2026-11-23）：

| 检查 | 方法 | 结果 |
|---|---|---|
| 文本层 | 逐文件扫描 `^\s*axiom` / `^\s*opaque` | **10 条 axiom、3 个 opaque**，逐条列出位置与数学内容 |
| 语句层 | 对每个关键定理取 `#print axioms` | `s71_main` = 3 基础 + `bgs3_pair_expansion` + `bgs5_khat_fourier_supp`；`pairCount_L1_bound` = 3 基础 + `N_L_lower_bound` + `pair_count_bound`；`zerosLChi5_bounded_finite`、`lfun_conj_symm` = **3 基础、零 axiom** |
| 反空条目 | 检查「自由算子 + ∃R 有界」型假设能否被平凡函数满足 | 抓到 1 对（`offcritSum` + `n3_remainder_uniform`，可被恒 0 满足）⟹ 判定为空条目并删除，登记为「未形式化」 |
| 反假命题 | 检查假设的区间是否超出可证范围 | 抓到 1 条（`lfun_dirichlet_series` 在 `0 < re s ≤ 1` 为假且全库 0 使用）⟹ 删除 |
| 语句自洽 | 检查归一化分母、求和域类型是否匹配定义 | 抓到 1 处（`bgs3_pair_expansion` 把 δ 当零点数当分母、又在无穷集上求和）⟹ 口径手术修正 |

**结论**：审计台不是只用来查对手的。它把「我们自己的假设清单」从 14 条虚账压到 **10 条真账 + 3 个 opaque + 1 条明账（未形式化）**，而且压掉的每一笔都留了理由与可复核的原语句。

## 4. 能力边界（能背书什么，不能背书什么）

**能背书**：

- 我们审的就是官方发布的那一份（密码学指纹）；
- 源码文本层没有 `sorry`/`axiom`/`opaque`/`unsafe`；
- 被引用的文件、行号、符号真的存在，且与论文描绘的位置一致；
- 核心陈述的形式化公理集干净，且与论文命题判等。

**不能背书**：

- 数学正确性。论文的 (M) 未证，任何审计都不能把它变成已证；
- kernel 层全量闭包（需要 48 GB 以上提交内存，本机不可达）；
- 语句「强度」的完全等价。我们做的是同一性与逐字对应，不是语义等价证明——后者需要人工数学判断。

## 5. 产品化形态：三档服务

| 档位 | 内容 | 交付物 | 周期量级 |
|---|---|---|---|
| L1 | 指纹与体量核验 | 一页报告：SHA-256、文件数、行数、声明分布 | 小时级 |
| L2 | 文本层全树扫描 | 报告 + 可复跑脚本 + 关键字节级证据 | 天级 |
| L3 | 语句层同物核验 + 公理抽取 | 报告 + 论文↔代码对照表 + `#print axioms` 原始输出 | 周级 |

**客户画像**：期刊与会议程序委员会（收到形式化附录时）、基金与评审机构、机构媒体的事实核查部门、形式化项目的发布方自身（自证清白比被动挨审便宜）。

---

## 6. 风险与前提

- **不替代同行评审**。我们只回答「有没有藏东西」，不回答「数学对不对」。
- **依赖源码可得性**。发布方只给 `olean` 不给源码，L2/L3 无法进行，只能做 L1。
- **判断需要人**。语句层是否「偷弱」最终是数学判断，工具只负责把候选差异摆到桌面上。

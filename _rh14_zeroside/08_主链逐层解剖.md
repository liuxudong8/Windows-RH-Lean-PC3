1. `SizeWindows` 不是孤岛——`ch_core:367` 现造并使用了它。

## §2 逐层原文与解读

### 2.1 L3：`rh_of_every` 只有三行

```lean

  rh_of_right (fun s hs => h 1 (1 : DirichletCharacter ℂ 1) s hs (Or.inl (by simp)))
```

取 `N = 1`、`χ = 1`，用 `LFunction_modOne_eq` 把 L 函数换成 ζ。**RH 的全部重量都压在 `EveryCharacter` 上，这一步零内容。**

### 2.2 L4：`EveryCharacter` 的定义

```lean
def EveryCharacter : Prop :=
  ∀ N [NeZero N] (χ : DirichletCharacter ℂ N) (s : ℂ),
    1 / 2 < s.re → (χ ≠ 1 ∨ s ≠ 1) → LFunction χ s ≠ 0
```

这就是 GRH-L 的逐字陈述。

### 2.3 L9 出口：`ZeroFreeAll` 等于 GRH-L

这是本轮最重要的定义级发现。`ExplicitFormulaErrorOfHostConditions.lean:11-18`：

```lean
def PChar.ZeroFreeAbove (ψ : PChar) (θ : ℝ) : Prop :=
  ∀ s : ℂ, θ < s.re → DirichletCharacter.LFunction ψ.χ s ≠ 0

def ZeroFreeOn (Q : PChar → Prop) : Prop := ∀ ψ : PChar, Q ψ → ψ.ZeroFreeAbove (1 / 2)

def ZeroFreeAll : Prop := ZeroFreeOn fun _ => True
```

展开后：

\[
\text{ZeroFreeAll} \;=\; \forall \psi\, \forall s,\; \tfrac{1}{2} < \operatorname{Re} s \;\Rightarrow\; L(\psi.\chi, s) \neq 0
\]

**`1/2` 不在参数里，在 `ZeroFreeOn` 的定义体里。** 所以任何输出 `ZeroFreeAll` 的定理，都必须已经拿到 `Re s > 1/2` 的零自由——不能靠"取 θ 再取极限"绕过类型检查。

### 2.4 L10：`zeroFreeOn_of_tiedWin_cyc` 的签名

```lean
theorem zeroFreeOn_of_tiedWin_cyc {Q : PChar → Prop} {la : ℝ} (hla : 1 < la)

```

注意 `hla : 1 < la`。这个 `la` 很容易被误读成"零自由区域的 θ"，实际不是。

### 2.5 L12：`la` 是窗口宽度，不是 θ

`Window.lean:7-8` 与 `:30-31`：

```lean
def HasWindows (S : Set ℝ) (la : ℝ) : Prop :=
  ∀ y : ℝ, ∃ Y : ℝ, y ≤ Y ∧ ∀ x : ℝ, Y ≤ x → x ≤ Y ^ la → x ∈ S

def FormBAt (la : ℝ) : Prop :=
  ∀ θ : ℝ, 0 < θ → θ < 1 → HasWindows {x | Λ.Gm x ≤ x ^ θ} la → Λ.ZeroFreeAbove θ
```

`HasWindows S la` 说的是：存在一段 `[Y, Y^la]` 的窗口，整段落在 `S` 里。**`la > 1` 表示窗口比 `[Y, Y]` 宽，这是窗口的宽度指数。**

`FormBAt la` 的 `θ` 才是零自由区域，取值范围 `(0, 1)`，与 `la` 无关。**所以"`la > 1` 但传入 `θ ≈ 1/2`"不是矛盾，是设计。**

### 2.6 L11：`level_of_tiedWin` 的 `θ → 1/2 + δ` 技巧

```lean
theorem level_of_tiedWin {Λ : Level} {la : ℝ} (h112 : ...) (hB : Λ.FormBAt la)
    (h : ChebyshevInequalityAtWindowScale @core @Tied la Λ) : Λ.ZeroFreeLevel := by
  ...
  refine hB (1 / 2 + min (s.re - 1 / 2) (1 / 2) / 2) (by linarith) (by linarith) ... ψ hψ s (by linarith)
```

给定 `s.re > 1/2`，取

\[
\theta \;=\; \frac{1}{2} + \frac{\min(\operatorname{Re} s - 1/2,\; 1/2)}{2}
\]

于是 `θ ∈ (1/2, s.re)`。`ZeroFreeAbove θ` 覆盖 `s.re > θ`，故覆盖这个 `s`。**这是标准技巧，不循环：不需要 `θ = 1/2`，只需要 `θ` 严格小于每个待证点的实部，再取任意接近。**

**所以"`ZeroFreeAbove(1/2)`"实际上被"对每个 `δ > 0` 有 `ZeroFreeAbove(1/2+δ)`"顶住。这一步合法。**

### 2.7 L14：`core_gm` 的结论

`CoreGm.lean:12-15`：

- **壳**（`GrowthBoundGivesRiemannHypothesis`、`GrowthInequalityDataExists`、`RiemannHypothesisOfBalanceAndGrowthData`）：仍是 `def : Prop`，未被证明，也未被主链使用。

## §5 强度账本：整个证明等价于一句话

把 16 层压缩，只剩一条命题：

\[
G_x \;\le\; x^{\,1/2+\varepsilon}\quad (\forall \varepsilon > 0)
\]

而 `Gx` 与 `Gm`、`Gz` 的关系是：`Gm = Gz + Σ wt·gChi`，`Gx` 是 `Gm` 在字符族上的版本。

而这一步到 RH 的转换，由 `ChebyshevGrowthImpliesZeroFree`（`ExplicitFormulaErrorOfHostConditions.lean:40-41`）完成：

```lean
def ChebyshevGrowthImpliesZeroFree : Prop :=
  ∀ θ : ℝ, 0 < θ → θ < 1 → ∀ y0 : ℝ, (∀ y ≥ y0, Λ.Gm y ≤ y ^ θ) → Λ.ZeroFreeAbove θ
```

**"`Gm` 增长被 `y^θ` 控制 ⇒ 零自由区域是 `Re s > θ`"。** 这是 Landau 型显式公式方法，是数学上正确的转换。

于是整条链等价于：

1. 证 `Gm(y) ≤ y^(1/2+ε)` 对任意 `ε > 0`（由 `core_gm` 完成，前提 `EAtH`/`CoreAtH`）；
2. 用 Landau 型转换把零自由区域从 `1/2+ε` 收到 `1/2`（由 `level_of_tiedWin` 完成）。

**第 1 步就是 RH 的等价形式；第 2 步是恒真技巧。所以全部重量在第 1 步，而第 1 步落在 `core_gm` → `ch_core` → `proposition_size_bound`。**

### 5.1 `1/2` 的完整来源链

`1/2` 不是输入，也不是"论证结果"，而是一条假设经算术后浮到结论常数位置：

1. `SizeWindows` 的 `hm1 : x^(1/2-ε) ≤ m`（假设）；
2. `proposition_size_bound` 的 `hxX`：从 `hm1` 得 `x ≤ x^(1/2+ε)·m`（`:522-526`）；
3. 其余初等不等式把这一个 `1/2` 传成 `Gx ≤ x^(1/2+(C+3)ε)`；
4. `core_gm` 把它变成 `Gm ≤ x^(1/2+(eD+eL+7)ε)`；
5. `level_of_tiedWin` 用 `θ → 1/2+δ` 把它收成 `ZeroFreeAbove(1/2)`。

这与我们自己的 `proposition_size_bound_alpha` 结构逐字同构：`α ≥ 1/2` 的门槛来自 `1 ≤ 2α + 3ε/2`，而 `α = 1/2` 这一侧正是 `hm1`。

**结论：`m` 不是被算术约束在 √x 的，是被 `SizeWindows` 的一条合取项钉在那里的。** 所以另给一个值（不是 1/2）确实给出"不同的 RH"——即不同的零自由区域常数。就这一点而言，最初的直觉是对的。

### 5.2 "没有痕迹"的解释

砖的清单里：Landau（1918）、Page（1935）、Linnik（1944）、Vinogradov（1958）、Siegel（1935）、Weil（1964）、Deligne（1974）、Fargues（2010s）。**没有一件是 1944 之后的新数学。**

把旧定理 Lean 化不会在数学界留下痕迹，只会在 Lean 社区留下工程量。所以"90 年没痕迹"不是异常，是**必然**：因为这些砖本来就是旧的。

**但这也带来一个无法回避的推论：若所有砖的强度天花板都在 1944 年，它们不可能推出 RH。所以如果链真的输出了 RH，必有一处强度高于砖。**

三处嫌疑（按位置排）：

1. **`primesRel_holds` 的 `hθ` 分支**（`PrimesInProgressionsRelativeError.lean:36-40`）——核过，取的是弱分支，不是放松。
2. **`ch_core` 的七个假设**（`HostFactsS`、`SizesA`、`ThinScales`、`CostWindows`、`RestSize`、`CharsA`、`gapA` 界）——**最大嫌疑，尚未核**。
3. **`HypsAlt` 的四十个字段**（`Hyps.lean:22-90`）——`Type 1`，装数据与条件，不含"零点"字样，但 `aAtG`、`irrC`、`zL`、`tie` 这些字段的实际强度未核。

**注意 `:419` 用 `hS.2.2.2.2.2.1` 取 `HostFactsS` 的分量——五层嵌套加投影。** 这写法说明它是深层嵌套数据包，字段按位置取。**这类结构最容易藏强度：只要某一层某个分量比文献原文宽，就无人可见。**

## §6 对 QRH 的取舍

### 6.1 该学的三件

**第一，接口纪律。** `ZeroFreeOn` 把 `1/2` 写在定义体里，所以任何 `ZeroFreeAll` 的输出都必须真拿到 `Re s > 1/2`。这个写法本身是干净的——它不给"取极限绕过"留口子。我们自己的链若要做形式化，应照这个做法：**把要证的常数写进定义，不留在参数里。**

**第二，struct 填充 + 单点总装的装配术。** 196 条 → 6 包 → 1 个 `Nonempty Hyps` → 3 个参数喂 `plugWin`。这套"多层结构体填充、最后单点调用"的组织方式，是形式化大工程唯一可行的架构。我们若做 QRH 的形式化，必须采用同样做法。

**第三，Landau 型转换的正确用法。** `ChebyshevGrowthImpliesZeroFree` 是"增长控制 → 零自由"的合法步骤，且它对 `θ` 是全称的（`∀ θ ∈ (0,1)`），不预设 RH。这是可借用的工具定理。

### 6.2 该改的三件

**第一，`hm1` 的位置。** 在他们的链里，"`m ~ √x`"是假设；在 QRH 里，这件事应当是**被推导出来的**。如果我们的方案能算出 `m` 的量级而不是选它，那才是真正不同的地方。

**第二，不要把 `1/2` 当端点。** 他们的 `α = 1/2` 是门槛下界（`1 ≤ 2α + 3ε/2`），所以 `α` 只能取 `≥ 1/2`，取更大则结论更弱。**QRH 若要独立，必须给出一个 `1/2` 由内蕴结构产生的机制**，而不是"选一个接近 1/2 的参数"。

**第三，与 Alpöge 的重叠区要主动避开。** 他们占的是"automorphic + Theta 提升 + Landau 转换"这条大路。我们若也走 Theta，就只是同一框架的弱版。**QRH 的独立靶点仍是那条：在 `SizeWindows` 里造出一组 $(m,k,n,nT,nT2,b,a_E)$ 使 $Gz(x) \le x^{1/2+\varepsilon}$，且 `m` 的量级由算术决定而非假设给定。**

**但必须诚实：这个靶点现在的表述还是"造一个见证"，不是"证一个定理"。** 差别在于——他们是在假设 `m ~ √x` 之后做完全部推导；我们要做的是**先证 `m` 必须 ~ √x**。这一步一旦成立，`1/2` 就从假设变成结论，那才是真正的独立贡献。

### 6.3 定位建议

按当前证据，建议：

1. **先把 Alpöge 的 `ch_core` 与七个假设读透**（这是他们唯一的数学承重点，也是最可能藏强度的地方）。读懂它，才知道"桥"到底哪一段是真的。
2. **QRH 暂不宣称任何 RH 结论**，改为"零侧常数机制"课题：研究 `m` 的量级能否由结构推出。
3. **形式化路线暂缓**，等 §7 的待查项清完再定。
